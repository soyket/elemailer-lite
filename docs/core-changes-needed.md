# Core file changes needed (main plugin files)

This is the working list of changes the plugin's own source files need. Each item names the file and function, what is wrong now, the change to make, and how to test it. Descriptions of the underlying problems are in docs/known-issues.md. Use item ids (C1, C2, ...) in branch names, commits and pull requests.

Rules for working from this list:
- One item (or a few tightly related items) per branch and pull request. Never bundle with the AI setup files.
- Items marked **owner decision** need an answer from the plugin owner before coding.
- After merging an item, tick it here and in docs/tasks/backlog.md, and remove it from docs/known-issues.md.
- C1-C8, C14, C28 and C32 are done on ai-native-dev-setup. Other items remain open.

## Security (do first)

- [x] **C1** `integrations/elementor/library.php` `my_template_delete_request()`: called `wp_delete_post( $template_id, true )` for any id with only `edit_posts`. Change: remove the delete AJAX handler, its registration, the unused `_myTemplateDelete()` JS caller, and the orphaned `confirmDeleteMessage` string. Test: the `wp_ajax_elemailer-lite-my-template-delete-request` action is not registered, and normal posts and Elemailer library templates remain after calls to that removed action. Confirmed from the full panel script: `_myTemplateDelete` was defined but never bound to a click, so the Lite interface did not call this action.
- [x] **C2** `integrations/elementor/library.php` `remote_request()` and `elementor_batch_process()`: `wp_remote_get()` on a URL from `$_POST['url']`. Change: only allow `https` and the host `lib.elemailer.com`; use `wp_safe_remote_get()` with a timeout; check `is_wp_error()` and the response code. Safe for the current import: the panel script only sends the template's `elemailer-page-api-url`, which PHP builds from `https://lib.elemailer.com/wp-json/wp/v2/elemailerlib/{id}`. Note `remote_request()` appends the `get_api_params()` values (`site_url`, empty `purchase_key`, `per-page`, `template_status`) to that URL, so the site URL is sent to the remote server. Test: template library still lists, previews and imports; a URL to another host is refused.
- [x] **C3** `integrations/elementor/library.php` `my_template_remote_request()`, `my_template_elementor_batch_process()` and `elementor_batch_process()`: (a) the first two read `_elementor_data` of any post id; (b) the two batch functions take the target post id from `$_POST['id']` and `Import::import()` overwrites that post's `_elementor_data`, with only `edit_posts` checked. Change: for the target post require `current_user_can( 'edit_post', $post_id )` and a post type of `em-form-template` or `em-emails-template` before calling `Import::import()`; for any source template id require post type `elementor_library` with the Elemailer type meta and `current_user_can( 'edit_post', $id )`. Confirmed from the full panel script: the Lite import sends `id` = `elementor.config.document.id` (the post being edited) to `elemailer-lite-elementor-batch-process`, so the target check will not break it; the two `my_template_*` actions are not called by the Lite script. **Owner decision:** remove the two unused `my_template_*` handlers instead of hardening them. Test: importing a free library template into an Elemailer template from the editor still works; as a Contributor, importing into an unrelated post id is refused.
- [x] **C4** `app/form-template/action.php` `get_template_setting()` (and the REST route in `core/api.php`): readable by anyone and returns the title of any post id. Change: require `manage_options` and `get_post_type( $id ) === 'em-form-template'`. Also in `update()`: require the same post type. **Must be done together with** `public/assets/js/admin/form-template-functions.js`: the GET sends `X-WP-Nonce` from `data-nonce` on the clicked link, but the nonce is printed on the form `#elemailer-modal-settings`; make the script send the form nonce for both calls. Test: Edit modal still loads for an admin; an anonymous request returns 401/403 or an empty result.
- [x] **C5** `helpers/notice.php` `dismiss()` and `enqueue_scripts()`: any logged-in user can set any user-meta key to `true` or create any transient with a chosen expiry. Change: `check_ajax_referer()` with a nonce printed by `enqueue_scripts()`; accept only ids starting `elemailer-sites-notice-id-`; `meta` only `user` or `transient`; `absint( $time )` with a cap. Test: dismissing the review notice still works and stays dismissed.
- [x] **C6** `integrations/elementor/base.php` `display_admin_notice_logic()`: updates options from `$_GET` without nonce or capability. Change: require `manage_options` and a nonce; build the Not Now and Never Show links in `display_admin_notice()` with `wp_nonce_url()`.
- [x] **C7** `core/global.php`: three AJAX handlers registered with `wp_ajax_nopriv_`. Change: remove the `nopriv` registrations; use `check_ajax_referer()` and `current_user_can( 'edit_posts' )`; return JSON with `wp_send_json_success()`; keep the `postTypeNonce` field name or update `integrations/elementor/assets/js/editor.js` in the same change. Test: Latest Posts and Selected Posts widget dropdowns still fill in the Elementor editor.
- [x] **C8** `app/form-template/action.php` `sanitize()`: values are copied unsanitized. Change: sanitize per field (`title`, `subject` with `sanitize_text_field`; `emailTo`, `emailFrom`, `emailReplyTo` with `sanitize_text_field` or `sanitize_email` as the field allows shortcodes, which needs an owner decision on allowed syntax).

## Correctness and robustness

- [ ] **C9** `integrations/elementor/widgets/video/video.php` Vimeo branch: `unserialize( file_get_contents( 'http://vimeo.com/api/v2/video/$vid.php' ) )` at render time. Problems: plain http, `unserialize` on remote data, blocking request on every render, no error handling (`$hash[0]` on failure), and the id is taken with `substr( $url, 18, 9 )`. Change: parse the id with a regex, fetch over https with `wp_remote_get()` and a timeout, decode JSON (or oEmbed), cache with a transient, and fall back to a default thumbnail. **Owner decision:** whether the old Vimeo v2 endpoint is still wanted; oEmbed is the usual replacement.

- [ ] **C13** `plugin.php` `load_js_css_admin()` and `show_free_version_limitation()`; `app/form-template/base.php` `modal_view()`: use `get_current_screen()` without a null check. Change: guard the result.

- [ ] **C15** `integrations/elementor/widgets/selected-posts/selected-posts.php` `render()`: renders any post id stored in the widget, with no status check. **Owner decision:** limit to published posts (`get_post_status( $post ) === 'publish'`).
